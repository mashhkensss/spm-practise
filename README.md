# TODO-лист

В рамках проекта создаётся TODO-лист, в котором пользователь сможет записывать свои задачки и отслеживать их выполнение. 

Возможности сервиса:
- завести задачу
- добавить к ней описание
- поставить дедлайн
- отсортировать задачи по дедлайнам
- отметить задачу выполненной
- перенести задачу на другой день

## Типы задач

###  `task`
- **Описание**: Реализация нового пользовательского сценария, расширение возможностей продукта.
- **DoR**
1) Задача описана
2) Присутствуют критерии приемки сформулированные в виде чек-листа
3) Задача оценена
4) Для задачи проставлены зависимости и блокеры

- **DoD**
1) Для задачи выполнены все критерии приемки
2) Обновлена документация
3) Написаны `unit-tests` (покрытие для нового кода >70%)
4) Проходят тесты в CI и все пайплайны зеленые
5) Код прошел `Code Review` и получил минимум 1-2 апрува
6) Ветка слита с основной веткой


### `bug`
- **Описание**: Устранение дефекта, некорректного поведения системы или несоответствия требованиям.
- **DoR 
  - Чётко описан **шаг воспроизведения** ошибки.
  - Указаны **ожидаемый** и **фактический** результат.
  - Если ошибка критична, приоритет должен быть высоким.
- **DoD 
  - Ошибка больше не воспроизводится (проверено по шагам).
  - Написан **тест**, который покрывает данный сценарий (regression-тест), чтобы ошибка не вернулась.
  - Документация обновляется только если изменилось поведение API или интерфейса.

### `research` 
- **Описание**: Проведение технического или продуктового исследования, анализ альтернатив, прототипирование, сбор данных.
- **DoR**:
  - Чётко сформулирован **вопрос**, на который нужно получить ответ.
  - Определены **критерии завершения исследования** что будет считаться результатом (документ, сравнительная таблица).
- **DoD:
  - Результаты исследования **задокументированы** (создан файл в `/docs`, обновлён README).
  - Сделана рекомендация для команды (какой путь выбрать).
  - Если исследование включает написание прототипа, код не обязан быть покрыт тестами на 100%, но должен быть воспроизводим.
  - Задача завершается, когда команда приняла решение на основе результатов.
