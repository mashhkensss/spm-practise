# MVP Passport TODO-лист

## 1. Контекст и цель MVP

**Продукт:** TODO-лист, в котором пользователь записывает задачи и отслеживает их выполнение.  
**Цель MVP:** проверить что пользователь может быстро завести задачу, указать дедлайн, увидеть список,
отметить выполнение и перенести задачу на другой день.

---

## 2. Пользовательские сценарии MVP

### US-01. Создание задачи

**Как пользователь**, я хочу завести задачу, чтобы не забыть о деле.  
**Сценарий:** открываю список → нажимаю «Новая задача» → ввожу заголовок, описание, дедлайн → сохраняю.  
**Критерии приемки:**

- Заголовок обязателен.
- Описание и дедлайн опциональны.
- После сохранения задача появляется в списке без перезагрузки страницы.
- При ошибке API показывается понятное сообщение.

### US-02. Добавление описания

**Как пользователь**, я хочу добавить описание к задаче, чтобы сохранить детали.  
**Критерии приемки:**

- Описание можно добавить при создании и редактировании.
- Описание отображается в карточке/деталях задачи.
- Пустое описание допустимо.

### US-03. Установка дедлайна

**Как пользователь**, я хочу поставить дедлайн, чтобы понимать срок.  
**Критерии приемки:**

- Можно выбрать дату.
- Дедлайн можно изменить или очистить.
- Дата отображается в списке.
- Задачи без дедлайна не ломают сортировку.

### US-04. Сортировка по дедлайнам

**Как пользователь**, я хочу видеть задачи по порядку дедлайнов, чтобы сначала делать срочное.  
**Критерии приемки:**

- Сортировка по возрастанию дедлайна.
- Задачи без дедлайна - в конце списка.
- Сортировка применяется после создания, изменения и переноса задачи.

### US-05. Отметка задачи выполненной

**Как пользователь**, я хочу отметить задачу выполненной, чтобы видеть прогресс.  
**Критерии приемки:**

- Есть чекбокс/кнопка «Выполнено».
- Статус сохраняется.
- Выполненная задача визуально отличается.
- Отметку можно снять.

### US-06. Перенос задачи на другой день

**Как пользователь**, я хочу перенести задачу, если не успел.  
**Критерии приемки:**

- Есть действие «Перенести».
- Можно выбрать новую дату.
- Новый дедлайн сохраняется.
- Список пересортировывается.
- Задача не дублируется.

## 3. Требования

### 3.1. Функциональные требования

| ID    | Требование                                              |
|-------|---------------------------------------------------------|
| FR-01 | Создание задачи с заголовком, описанием, дедлайном.     |
| FR-02 | Просмотр списка задач.                                  |
| FR-03 | Редактирование заголовка, описания, дедлайна.           |
| FR-04 | Сортировка списка по дедлайну: asc, nulls last.         |
| FR-05 | Отметка задачи выполненной/невыполненной.               |
| FR-06 | Перенос задачи на другой день через изменение дедлайна. |
| FR-07 | Сохранение задач между перезагрузками/перезапусками.    |
| FR-09 | Валидация входных данных и обработка ошибок.            |

### 3.2. Нефункциональные требования

| ID     | Требование                                       |
|--------|--------------------------------------------------|
| NFR-01 | Веб-интерфейс, адаптивность под desktop/mobile.  |
| NFR-02 | Загрузка списка до 100 задач не более 1 секунды. |
| NFR-03 | Данные не теряются после reload/restart.         |
| NFR-04 | Unit-тесты для нового кода, покрытие >70%.       |
| NFR-05 | CI зелёный: lint, tests, build.                  |
